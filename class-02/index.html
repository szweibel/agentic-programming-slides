Three settings

MODEL

Which model does the work. Models differ in speed and capability.

THINKING

How much reasoning effort it uses. Higher settings can take longer.

APPROVALS

When it needs your permission. Some actions can run without asking.

Show where each setting is and which approval setting to use today. Check the default before class; it changes between versions. If students use different models or settings, record that before comparing their results.

The same request on each computer

Build a small web app for New Yorkers to explore the most recent full week of NYC 311 service requests from NYC Open Data. Let people compare complaint types and boroughs. Show where the data came from and which dates it covers. Start it so we can open it in a browser.

Use last week's prompt exactly. The most recent full week has changed.

Use the same prompt so the results can be compared. Check the dates before comparing totals with last week's app. Students may also interpret the start of a week differently; that is one of the choices to discuss.

Where the numbers come from

The agent writes a program that counts the city's records. We can follow a number back to those records and check the calculation.

Show where the run fetched the city's records. Students may expect the model to invent numbers as it writes an answer. Here, the agent writes code, and that code calculates the counts from records we can inspect. Checking one calculation helps students understand why they can trust that result. If it differs, investigate the dates, filters, and counting steps. This is ordinary checking of a data program. Sources in notes/trust-and-verification-research-2026-09-06.md.

Check the page against the data

Pick a borough. Does the count change?

Spot-check five records. Are their dates within the week you asked for?

Pick one count. Check it against the data file or the city's site, using the same dates and filters.

Narrow the browser window. Can you still read and use the page?

Do the third check even if you skip the rest. Have the agent count the same borough and complaint type from the raw file, without using the app's counting code. If the counts differ, compare the dates and filters before diagnosing a bug. Matching counts check the calculation against the file; they do not prove the download is complete. Five records are a spot-check, not a check of every date.
