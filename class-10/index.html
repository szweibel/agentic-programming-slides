Code quality and building an agent

DHUM / DATA 70600 · Class 10

Code quality

  • Does it do what you asked?
  • Can someone else read it and change it?
  • Does it still work after other changes?

AI slop in code

  • Code you can run but can't easily maintain
  • The same code copied into several places
  • Errors caught and then ignored
  • Made-up default values in place of missing data
  • Leftover code that isn't used anywhere
  • GitClear found copied code rising from 8% to 18% of all changes as more programmers used AI tools
  • GitClear couldn't tell who wrote each line

Linters

  • With a linter, you check code against written rules without running it
  • Some rule sets are written for patterns agents tend to produce
  • The CUNY AI Lab uses a rule set called anti-slop on its projects

Tests

  • With a test, you run part of the program and compare the result with what you expected
  • Agents often write tests without being asked
  • When the result doesn't match, some models change the test instead of the code
  • In one study, people found more bugs with tests they wrote than with tests a model wrote

Running the checks

  • Run the linter, run the tests, and use the page yourself
  • Ask Codex to show you the output of each check, not just say it passed
  • Simon Willison: "If the code has never been executed it's pure luck if it actually works"

Building a web agent

Web agents

  • Simon Willison: an agent "runs tools in a loop to achieve a goal"
  • On a web page, the agent can filter the data, draw a chart, or highlight rows

API keys

  • Any visitor can read every file on a GitHub Pages site, including a key
  • OpenAI: "Never deploy your key in client-side environments like browsers or mobile apps"
  • You can keep the key on a small server, such as a Cloudflare Worker, and send requests through it

Other options

  • Visitors sign in with their own account, for example through OpenRouter
  • You run a small model in the visitor's browser, with no key
  • Visitors need a large download and a recent computer

Libraries

  • Codex can use Vercel AI SDK, CopilotKit or assistant-ui to add a chat window with tools to a page
  • With all three, the agent can change the page in the visitor's browser
  • With all three, you still need a small server for the key

Tools for a dataset

  • Search or filter the dataset
  • Count and summarize
  • Draw a chart
  • Highlight the matching rows on the page
  • Link each answer to its rows
  • OWASP: give it only the tools it needs, and read-only access where possible

Examples

  • London Museum built Clio to answer from the museum's own pages, and warns visitors that dates and titles may be simplified
  • Harvard Library built Collections Explorer for searching its finding aids
  • The CUNY AI Lab built Library Assistant for library pages and LibGuides. It searches the catalog and cites its sources.
  • In GlassDB, the model writes a database query, and GlassDB runs it in the visitor's browser and draws a chart

Ideas

  • A guide to a dataset on your site: ask a question, see the matching rows and a chart
  • A reading companion for a text or archive you've put online
  • A tutor on a page you teach from
  • A guide to a collection or exhibit

Problems

  • Wrong answers that look right, especially counts and dates
  • Text inside the dataset can contain instructions to the agent
  • You pay for every question visitors ask

Decisions

  • Which model it uses
  • Which tools it has
  • What it can read and change
  • Where the key lives
  • What it says when it doesn't know
